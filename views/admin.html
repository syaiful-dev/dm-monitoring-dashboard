📧 Missing-File Alert Email

The email draft shown when an operator clicks "Review" on an alert.
Used when a workflow has no specific recipient below. Supports {buyer}.
Placeholders: {buyer} {workflow} {expectedDay} {lastReceived} {avgPerDay} {avgFirstArrival}

📤 SMTP Server (send email)

Configure the mail server the app uses to send the alert email. When disabled, clicking "Send Alert Email" will report that sending is off.
The password is stored on the server (in config/settings.json, git-ignored) and is never shown back here. Save settings first, then use "Test connection".

⏰ Re-alert Window

After "Review", if the file is still missing, the alert re-surfaces after this many minutes.

📮 Per-Workflow Recipients

Search for a workflow, enter its recipient email, and click Add. Only workflows with a specific recipient are listed below; all others use the default recipient above. Separate multiple emails with commas.

🎯 Priority Buyers

Buyers monitored for missing-file alerts. The keyword is matched against the WORKFLOWID (case-insensitive). The display name is a friendly label shown in the UI.
Buyer keyword (matches WORKFLOWID) Display name (optional)

🧩 Monitored Workflows (exact)

Full WORKFLOWID values to monitor in addition to the buyer keywords above. Matched exactly and monitored regardless of document type. One per line.
Optional: pin a workflow to a specific database with dbName | WORKFLOWID so it's only queried there (faster — avoids scanning the other databases). Without a db | prefix, the workflow is searched on all databases.
Format: dbName | WORKFLOWID or just WORKFLOWID. Case-sensitive, matched with =. Blank lines ignored.

📄 Document Types

Only these document types are pulled from the database. The query filters on DOCTYPEID (e.g. WHERE DOCTYPEID IN ('ORDERS','INVOIC')). If none are selected, all types are included.

🗄️ Database Connections

All configured connections — MSSQL or MySQL (defined in the server .env as TREND_DB1_* … TREND_DB5_*, each with TREND_DBx_CLIENT). Their data is combined into one view. Each row's source is tagged. Testing only checks login + reachability (SELECT 1) — no data query is run.

📝 Query

The SELECT run against every connection. Must return columns: DOCID, WORKFLOWID, DOCFILENAME, DOCSIZE, CREATIONDATE, STATUS, and optionally METADATA, RECEIVEDATE. Filters for priority buyers, document types, and the history window (set in the Trend & Analysis tab) are applied automatically.
Note: the DB is only used when TREND_SOURCE=db in .env. 

      

    


    
    

      

        
📈 Trend & Analysis — half-month snapshot

        

          The Trends & Analysis tab is built from a half-month snapshot: the daily
          summary for the most recently completed phase — days 1–14 or
          days 15–end of a month — captured with no row cap and saved
          to disk. The database is read twice a month; the snapshot refreshes
          automatically on the 1st and the 15th (when a new phase
          completes), so restarting the app never re-queries the DB.

🛡️ Alerts data — history window

        

          The Alerts tab pulls recent documents (not the snapshot) to detect missing
          files. It loads everything received in the last N days — a date window, so
          every workflow with recent activity is covered (a busy workflow can't crowd out a quiet one).
        

        
        
        

          Recommended: 3 (minimum ~2 for missing-file detection to work — it compares day-to-day). Larger values load more data (slower start, more memory).
